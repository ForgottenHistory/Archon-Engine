# Scripting

Archon runs Lua 5.2 scripts for content that is logic: what an event does, when a decision is available, how much an AI wants something. Scripts can be changed without a recompile, generated by tools, and shipped by mods.

The ENGINE provides one thing: a sandboxed Lua world you give C# functions and objects to, and call into. It defines no script functions about provinces or countries. Those are your GAME's.

For the design and its rules, see [Scripting (architecture)](../Engine/scripting.md). This page is the how-to.

## Setup

The `Scripting` assembly is always compiled and referenced automatically. Add `using Scripting;`. Your code never references the Lua library itself.

```csharp
var engine = new ScriptEngine();
```

Make one engine for your game (or one per kind of content) at load, and keep it.

## Give scripts something to call

### A global function

```csharp
engine.SetFunction("log_event", (ref ScriptCall call) =>
{
    string text = call.String(0);           // first argument
    ArchonLogger.Log(text, "game_events");
});
```

### An object with methods

Scripts work best when they hold your game's objects and call methods on them.

```csharp
sealed class CountryScope : ScriptObject
{
    public readonly ushort Id;
    public CountryScope(ScriptType type, ushort id) : base(type) { Id = id; }
}

ScriptType country = engine.DefineType("country");

country.SetMethod("gold", (ref ScriptCall call) =>
    call.Return(economy.GetGold(call.Self<CountryScope>().Id).ToDouble()));

country.SetMethod("add_gold", (ref ScriptCall call) =>
{
    var c = call.Self<CountryScope>();                         // argument 0 is the object
    economy.AddGold(c.Id, FixedPoint64.FromDouble(call.Number(1)));   // c:add_gold(200) -> 200 is argument 1
});
```

Make **one object per thing**, once (a dictionary from country id to its `CountryScope`). Lua compares objects by identity, so `a:owner() == b` only works when both are the same C# object. It also means nothing is allocated per call.

### Reading arguments

| Call | Reads |
|---|---|
| `call.Number(i, fallback)` | a number |
| `call.String(i)` | a string, or null |
| `call.Bool(i, fallback)` | a boolean (the fallback is true: `c:at_war()` and `c:at_war(true)` read the same) |
| `call.Object<T>(i)` / `call.Self<T>()` | one of your objects, or null |
| `call.Table(i)` | a Lua table (`ScriptTable`) |
| `call.Function(i)` | a Lua function to call or keep (`ScriptFunctionRef`) |
| `call.Count`, `call.Has(i)` | how many arguments, whether one is there |

An argument that is missing or of another kind reads as the fallback. `call.Fail("message")` stops the script with an error.

### Returning

`call.Return(value)` for a boolean, number, string or object; `call.ReturnList(list)` for a list of objects the script loops with `ipairs`. A function that returns nothing just ends.

## Let scripts register content

The usual shape: a script file calls one of your functions with a table, and you keep what is in it.

```lua
-- decisions/economy.lua
decision {
  id = "raise_taxes",
  cost = 50,
  available = function(c) return c:gold() < 100 and not c:at_war() end,
  effect = function(c)
    c:add_gold(200)
    c:add_stability(-0.05)
  end,
}
```

```csharp
sealed class Decision
{
    public string Id;
    public int Cost;
    public ScriptFunctionRef Available, Effect;
}

engine.SetFunction("decision", (ref ScriptCall call) =>
{
    ScriptTable t = call.Table(0);
    decisions.Add(new Decision
    {
        Id = t.String("id"),
        Cost = (int)t.Number("cost"),
        Available = t.Function("available"),    // kept: compiled once, called many times
        Effect = t.Function("effect"),
    });
});

foreach (string file in files)          // sort the files: the order should be the same on every machine
    engine.RunFile(file);
```

## Call into scripts

```csharp
bool can = engine.CallBool(decision.Available, countryScope);            // false if the script failed
double weight = engine.CallNumber(decision.AiWeight, countryScope, 1);   // 1 if it failed
bool ok = engine.Call(decision.Effect, countryScope, out _);
```

A function a table did not have is not valid (`ScriptFunctionRef.IsValid`): check before calling, and decide what its absence means (a missing `available` usually means "always").

### Calling back from a method

A method can run a function the script passed to it:

```csharp
// c:any_neighbor(function(n) return n:at_war() end)
country.SetMethod("any_neighbor", (ref ScriptCall call) =>
{
    var filter = call.Function(1);
    foreach (var neighbor in NeighborsOf(call.Self<CountryScope>().Id))
        if (call.Engine.CallBool(filter, neighbor)) { call.Return(true); return; }
    call.Return(false);
});
```

## Effects belong in commands

A script effect changes game state, so run it where any other state change runs: inside a command's `Execute`, or in a tick. Never from UI code.

```csharp
public override void Execute(GameState gameState) =>
    decisions.Engine.Call(decisions.Get(DecisionId).Effect, decisions.Scope(CountryId), out _);
```

Triggers (`available`, AI weights) only read, so the UI and the AI may call them freely.

## Keep it deterministic

- **Do the maths in C#.** Scripts pass numbers to your functions; convert to `FixedPoint64` there. Do not compute simulation values in Lua.
- **Keep state in C#.** A flag or counter a script sets goes through one of your functions into game state. Lua variables are not saved and not synchronised.
- **No `math.random`.** It is removed. Give scripts your own random function on a `DeterministicRandom` you seed from game state.
- **Loop over lists, not `pairs`.** Give scripts lists with `ReturnList`; read tables by field name or `ScriptTable.FieldNames` (sorted).

## When things go wrong

Nothing a script does throws out of the engine.

- **Errors.** `Run` and `Call` return false; `engine.LastError` has the message with the script's file and line; the `Error` event fires; a warning is logged. The engine keeps working.
- **Endless loops.** A call is stopped after `InstructionLimit` instructions (50 million by default).
- **A method your type lacks.** The script goes on: the call returns false, and the name is reported once (`MissingMember` event, `Missing` list, a warning). This lets content be written, or converted from another game, ahead of your code. `Missing` is then your to-do list.
- **A global that doesn't exist** is a normal Lua error, unless you make the engine with `new ScriptEngine(stubMissingGlobals: true)`. Use that for converted content only: for hand-written scripts it would hide typos.

### Content far ahead of the game

With a large converted set, hundreds of names can be missing at once:

- Set `engine.LogMissing = false` and collect the names from `MissingMember` instead of the log.
- A missing trigger answers false, so `not c:missing_trigger()` answers true. Where a wrong yes would do something, compare `engine.MissingCalls` before and after the call: if it grew, the answer leaned on a missing name and means "can't tell".
- A call on the result of a missing method (`c:missing():other()`) is an error. Return a stand-in object, about which everything is false, where a lookup finds nothing, rather than nil.

## What scripts can use

The `base`, `string`, `table`, `math` and `bit32` libraries. There is no file access, no `os`, no `require` or `load`, and no `debug`. `print` writes to the log.

## Cost

A Lua function that makes two calls into C# takes about a microsecond and allocates nothing. That is fine for decision points (an AI choosing, a tooltip opening, an effect firing). Per-province work every tick belongs in C#.
